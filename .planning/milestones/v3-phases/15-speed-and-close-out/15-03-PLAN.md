Parse (D-02): `--bench-state` is a standalone switch parsed beside `--hash-audio` (before a value is taken); a repeat gives usage("--bench-state may be specified once"), and without `--bench` the validation block gives usage("--bench-state requires --bench"). Add options fields `int bench_state`, `uint64_t *bench_save_ns`, `uint64_t *bench_load_ns`, `uint8_t *bench_state_buf` (all freed by free_options).

Loop (D-02, D-04): after the ROM loads and before the loop, size the buffer once with nesturbator_state_size and allocate it and both sample arrays (the out-of-memory path as for bench_frame_ns). After each timed frame's hash and audio work (where the loop body ends, before `done_frame = n`), time `nesturbator_save_state(inst, buf, size)` and then `nesturbator_load_state(inst, buf, size)` separately, with clock readings around each call only; a status other than NESTURBATOR_OK prints `nesturbator-run: bench save failed at frame <f>` or `nesturbator-run: bench load failed at frame <f>` and sets status to RUNNER_EXIT_FAILURE (exit 1, a failed operation, not a rejected input). The frame_us sample stays the frame call alone. In the report call pass bench_save_ns and bench_load_ns when bench_state is set (NULL otherwise), so the save_us and load_us lines follow frame_us.

Why the failure branch has no ci test (rule 6, W3): no route reaches it without a production-only fault-injection hook, which this plan does not add. By the contract in include/nesturbator.h, nesturbator_save_state fails only on a NULL instance or buffer, no cartridge, or a capacity below nesturbator_state_size; nesturbator_load_state of the bytes just saved by the same instance fails only if the core breaks its own round-trip contract. Under `--bench` the cartridge is always loaded (D-03 requires `--rom`, and a ROM that does not load exits before the loop), the buffer is allocated non-NULL from nesturbator_state_size of that cartridge before the loop, and the load reads the bytes the save just wrote, so neither call can fail from the command line. The Phase 13 runner save-failure tests (runner_save.cmake, the `--save-dir` cases) fail file I/O, which `--bench-state` never does, so their pattern does not transfer. The core's own refusals (every load check, BUFFER_TOO_SMALL, no cartridge) are already covered by the state.* tests. The branch is therefore defensive: it keeps D-02's message and exit 1 if the core ever regresses. The acceptance criteria pin its shape in source: both messages exist and each sets RUNNER_EXIT_FAILURE.

Help and README together, in this same commit (D-06, so the two-way check never sees one without the other): add `  --bench-state        with --bench, also save and load the state after every frame and time each` to print_usage beside the `--bench N` line, and a README bullet ``- `--bench-state` `` saying it needs `--bench`, the save and load are timed separately from the frame so frame_us stays comparable, it adds the save_us and load_us lines, a save or load failure exits 1, and stdout is unchanged.

Tests (D-07): extend runner_bench.cmake MODE=nohash with the third run `--bench K --bench-state --hash-frame K --hash-audio`, compared byte for byte against the `--frames` run. Register `runner.bench.format_state` (MODE=format, -DSTATE=1, same ROM, LABELS bench). Commit as feat(15-03).

Readiness (D-03, D-04): stdout to a pipe is fully buffered and the runner flushes it only on the exit and stop paths, and D-03 forbids `--state-at-frame` under `--bench`, so the ready.state channel other signal tests use is unavailable. The channel chosen: under `--bench` only, call `fflush(stdout)` right after printing a `frame … sha256` line. The flush happens after t1, outside the timed region, so frame_us is unaffected (D-04), and stdout's bytes are unchanged, so runner.bench.nohash still passes. A non-zero return from that flush is handled as the exit-tail flush failure is (status RUNNER_EXIT_FAILURE). Other run modes keep their buffering, so case_second_in_flush's assumption holds. Add one clause to the README `--bench N` bullet: each hash line is flushed as it is printed.

Signal test (D-03): add case `bench` to tests/runner/test_signal.c: create a pipe, spawn `--rom <fixture>/battery.nes --bench 1000000 --hash-frame 1` with stdout on the pipe's write end and stderr redirected to the work-dir runner.err file as the other cases do; close the parent's write end; read the pipe until a line starting `frame 1 ` arrives (the runner prints it after frame 1, which is after the handlers are installed), polling with the READY_DEADLINE_MS deadline, else kill_and_fail. Then keep draining the pipe (so a full pipe cannot delay the stop, as the README's POSIX launcher advice says), send the case's signal, reap within EXIT_DEADLINE_MS, require exit 0, and require runner.err to contain a `nesturbator-run: bench frames=` line and a `nesturbator-run: bench frame_us ` line, both before the `nesturbator-run: stopped by signal after frame` line. Write it as `case_bench(int sig)` and dispatch `bench` to SIGTERM and `bench_int` to SIGINT (I1, the same one-line split case_graceful uses for term and int). Register `runner_signal_case(bench)` and `runner_signal_case(bench_int)` beside the other cases inside `if(NOT WIN32)`, and add both names to the cases comment at the top of test_signal.c.
