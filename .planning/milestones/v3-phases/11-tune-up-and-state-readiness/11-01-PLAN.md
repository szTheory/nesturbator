## Decisions taken under Claude's discretion and orchestrator resolutions

- **C1 (D-04):** today's interval behaviour stays: a failed interval flush ends the run with status 1 and the exit flush retries. `runner/main.c` frame-loop flush logic is not changed; only the message text and the two tests that match it change.
- **C2 (D-06):** the runner-level test uses a non-empty directory at `<save-dir>/battery.sav.tmp`. A directory at the `.sav` itself makes the loader exit 4 first (open WR-03, out of scope).
- **C4 (D-06):** no CTest skip. The chmod case probes writability and passes with a `note:` line when the directory is still writable; the ENOTDIR case cannot be bypassed by root.
- **RLIMIT_FSIZE test:** a separate executable, because the limit applies to every file the process writes.
- **Windows sharing-lock test:** not added; directory-at-target already covers a failed `MoveFileExA`.
- **Directory at `.tmp` (checker fix, PROH-11-01-01):** the helper stats `<path>.tmp` before anything else and refuses any directory there, empty or not, with `EISDIR`. An unconditional `remove(tmp)` is wrong: POSIX `remove()` deletes an empty directory (probed: returns 0, directory gone) while Windows `remove()` does not, so it would both destroy a directory the helper did not create and behave differently by platform. Only a regular-file stale `.tmp` is removed.
- **Windows reason text:** a failed `MoveFileExA` reports `Windows error <GetLastError()>` as the reason; every other failure uses `strerror` of the saved `errno`.

In `runner/save.c` add `int nesturbator_run_file_replace(const char *path, const uint8_t *data, size_t size)`. Build `<path>.tmp` in a `char tmp[4096]` with `snprintf`; a name that does not fit reports `ENAMETOOLONG` and returns 1. Then stat `tmp` (POSIX `stat` and `S_ISDIR`; Windows `_stat` and `(st.st_mode & _S_IFDIR)`): if it exists and is a directory, empty or not, set errno to `EISDIR`, report it through `report_failure` and return 1 without removing anything, so the old file and the directory stay untouched (PROH-11-01-01). If it exists and is not a directory, it is a stale leftover from a killed write: `remove(tmp)` with the result ignored. Never call `remove(tmp)` before this check: POSIX `remove()` deletes an empty directory. A symlink at `tmp` is followed by `stat`: a link to a regular file is removed as a stale leftover (the link, never its target), a link to a directory is refused like a directory, and a dangling link makes the exclusive create fail with `EEXIST`, which is a failed save with the old file kept. Then `fopen(tmp, "wbx")`; if that returns NULL, report the saved `errno` and return 1 without removing anything (this call created nothing). Otherwise `fwrite` the whole size, `fflush`, sync (a small static `sync_stream` using `fsync(fileno(f))` on POSIX, `_commit(_fileno(f))` on Windows), and a checked `fclose`, capturing `errno` at the first failure. Then `rename(tmp, path)` on POSIX or `MoveFileExA(tmp, path, MOVEFILE_REPLACE_EXISTING | MOVEFILE_WRITE_THROUGH)` on Windows, capturing `GetLastError()` there. On any failure after the successful `fopen`: `remove(tmp)`, then print one line through a static `report_failure`: `nesturbator-run: cannot save <path> (<reason>); the previous save is kept` (reason = `strerror` of the saved errno, or `Windows error %lu` for the MoveFileExA case), return 1.
