Take the latest completed CI run on the branch head left by Plan 07 (`gh run list --branch gsd/phase-14-runner-process-contract --workflow ci.yml --limit 1`). From `gh run view <id> --log` read, per job, the CTest result line of every runner.signal.* test on the four Linux and macOS build legs and the `asan` job (`Passed <s> sec`), any `signal-to-exit <n> ms` lines the log carries, and the wall time of runner.stop.win_console on both Windows legs if Plan 07 kept it. The ci and asan test presets print test output only on failure, so a passing leg's `signal-to-exit` value is usually absent; a passing leg is the evidence that the helper's own 2000 ms assertion held on it.

D-15 rule, stated here so a failure on a hosted leg has a defined response: the bound is 2000 ms on every leg, the `asan` job included. If any leg fails a runner.signal.* test, or logs a `signal-to-exit` above 2000 ms, then (1) record in the SUMMARY the value, the case, the leg (for example `asan`) and the run URL, from `gh run view <id> --log-failed`; (2) do not raise the 2000 ms bound in tests/runner/test_signal.c, add a per-leg or asan-only bound, raise a TIMEOUT to absorb it, or skip, disable or retry the test (PROH-14-08-01); (3) find and fix the cause (runner side: the stop path between the flag and exit, the exit flush or fsync; test side: timing from the wrong instant or a readiness wait that ends too early), push, and read the new run; (4) if the cause cannot be fixed in this plan, stop and report it as a blocker with that evidence instead of continuing.

When every leg passes: rewrite the single line Plan 06 created as `set(NESTURBATOR_SIGNAL_TIMEOUT <n>)  # runner_signal_case timeout: twice the slowest hosted run: CI run <id> (<job name>), ENGINEERING section 5`, with `<n>` twice the slowest runner.signal.* wall time across those five jobs, rounded up to a whole second; keep the value and the comment on that one line. Set runner.stop.win_console's TIMEOUT (if kept) to twice its slowest Windows wall time with a comment in the form `# twice the slowest hosted run: CI run <id> (<job name>), ENGINEERING section 5`. Commit, push, and wait for the run on that head with `gh run watch <id> --exit-status`. Record in the SUMMARY the per-job wall times, any signal-to-exit values, the chosen TIMEOUTs and the measured run id.
