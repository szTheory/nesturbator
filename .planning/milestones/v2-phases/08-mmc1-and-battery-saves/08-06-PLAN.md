## Decisions taken under Claude's discretion

- **Helper names** carry the `nesturbator_run_` prefix the runner's other modules use (`nesturbator_run_write_ppm`, `nesturbator_run_audio_hash_*`).
- **Fixture bytes come from a C writer, not CMake.** CMake strings cannot hold NUL bytes. `runner.save_rom DIR` writes every ROM and seed file, as a `FIXTURES_SETUP` test, under the build tree only (CLAUDE.md rule 3; research "Clean tree").
- **The load is proven by a seeded byte.** `battery.nes` copies `$6100` to `$6004` at boot. A seeded `.sav` with `$42` at offset `0x100` therefore comes back with `$42` at offset 4, which only happens if the file was loaded before the first frame.
- **The mtime check uses `file(TIMESTAMP ... "%Y-%m-%dT%H:%M:%S.%f" UTC)`,** as `run_retroarch.cmake` already does. A rewrite inside the same microsecond is not possible, because a run takes milliseconds.
- **The kill test uses `execute_process(TIMEOUT 4)`,** which ends the child on every platform (research Pattern 8, verified locally). No `fork` or `TerminateProcess` driver is written.
- **Estimate above the 100000 smart-zone budget, kept as one plan.** The three tasks extend one fixture writer (`tests/runner/save_rom.c`), one case script (`tests/cmake/runner_save.cmake`) and one save module in sequence: Task 2's refusal cases and Task 3's interval and JAM cases are new `-DCASE` branches over Task 1's fixture and flush path. Splitting would make a second executor re-read the runner's 750-line `main.c` and the script to rebuild that harness, which costs more than it saves. The estimate is uncalibrated (sample count 0). The owner accepted this over-budget estimate unsplit on 2026-10-10.
- **Wave 4 after Plan 05** because the fixture `battery.nes` runs on the MMC1 board and both plans edit `tests/CMakeLists.txt` and `README.md`.
- **Runner messages:** the SAVE-03 line is fixed by D-19. Others are `nesturbator-run: cannot read <path>`, `nesturbator-run: cannot write <tmp>` and `nesturbator-run: cannot replace <path>; the new save is in <tmp>`.

`runner/save.h` and `runner/save.c`, with the declarations in the artifacts table:
- `save.c` starts with `#define _POSIX_C_SOURCE 200809L` before any include (C6). On `_WIN32` it includes `<io.h>` and `<windows.h>`, otherwise `<unistd.h>`.
- `nesturbator_run_save_path` applies D-18's stem rule.
- `nesturbator_run_save_load`:
  - `fopen(path, "rb")` NULL with `errno == ENOENT` gives FRESH; any other open or read failure prints `nesturbator-run: cannot read <path>` and gives ERROR.
  - On a length different from `size`, it prints `nesturbator-run: <path> is <a> bytes; the cartridge's battery RAM is <b> bytes` and gives MISMATCH.
  - Otherwise it reads exactly `size` bytes into `span` and gives LOADED.
  - It never opens the file for writing.
- `nesturbator_run_save_flush` writes `<path>.tmp` with fopen `"wb"`, fwrite, fflush, then `fsync(fileno(f))` (or `_commit(_fileno(f))` on Windows), and a checked fclose. It then calls `rename(tmp, path)` (or `MoveFileExA(tmp, path, MOVEFILE_REPLACE_EXISTING | MOVEFILE_WRITE_THROUGH)` on Windows), copies `span` into `shadow` and returns 0.
  - On any failure it prints a message and returns 1. A failed rename names the kept temp file.
  - `remove` followed by `rename` and `ReplaceFile` are not used (D-19 records why).
- Add `save.c` to the `nesturbator-run` sources in `runner/CMakeLists.txt`.
