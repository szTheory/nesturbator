## Decisions taken under Claude's discretion

- **`vblank_suppress` cleared with the position.** It records a `$2002` read racing the vblank set at the position the PPU leaves; kept, it would suppress the first vblank after reset. Rendering pipeline state is left alone: rendering is off (`mask = 0`) until a `$2001` write lands after 261/1, and the pre-render line refills it.
- **`$4017` re-apply through the existing delay path** (`frame_reset_delay = bus.apu_get_put_phase != 0 ? 2 : 1`), not a direct `frame_cycle = 0`: it reproduces NESdev's "as if the APU's $4017 were written 10 clocks before the first code starts executing" exactly with the documented 3-or-4-cycle delay, and keeps the 5-step quarter/half clocks a real write generates (RESEARCH "Reset facts confirmed against NESdev").

## Flagged assumptions

- **Frame IRQ cleared at reset (recorded open item, D-16):** no NESdev wiki page fetched on 2026-10-10 states it; the source is the blargg `apu_reset` readme (`irq_flag_cleared`). The plan keeps the clear as D-16 says; the deferred `apu_reset` ROMs are the check.
