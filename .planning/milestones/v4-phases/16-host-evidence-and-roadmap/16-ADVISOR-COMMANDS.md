## Trustworthy command confirmation

| Option | Pros | Cons | Complexity | Recommendation |
|--------|------|------|------------|----------------|
| Existing sh/nc, one-shot actions, closed-loop postconditions, fail on ambiguity | Reuses pinned macOS tools and current harness, preserves honest failure, smallest transport surface | Shell timer/process handling needs care, nc alone cannot supply missing protocol request IDs or prove arbitrary delayed delivery absent | Session script, owned oracle/check fixtures, CMake registration and artifact step -- Risk: stale artifacts and subprocess deadlines | Rec if strict parsing, bounded subprocesses and unique-epoch artifacts suffice; preferred starting policy |
| sh orchestration plus tiny owned POSIX test transport/deadline helper | Monotonic absolute deadline, explicit peer and socket lifecycle, bounded reply parsing, deterministic fault injection | Additional test-only C/socket code, still no server request IDs or action acknowledgments | One test helper, script wiring and focused controls -- Risk: endpoint reuse and overengineering | Rec if shell/nc cannot demonstrate bounded response attribution and process supervision; keep helper narrow |
| Entire-session fresh restart after ambiguity, using either transport | Abandons uncertain machine state, can distinguish transient startup failures | More host work and artifacts, risks masking recurring command defects, must isolate old epoch and pending datagrams | Attempt lifecycle, unique directories/ports, artifact manifest and terminal policy -- Risk: green-by-retrying and old epoch contamination | Rec only if measured host flake justifies it and ambiguous action remains a failed reported attempt; not default CI recovery |

**Rationale:** Begin with sh/nc and an explicit command policy: retry read-only requests within deadlines, send non-idempotent actions once, confirm their distinct postconditions before proceeding, and fail when evidence remains ambiguous. A tiny owned test-only helper is justified only by a demonstrated inability to enforce wall-clock budgets or correlate replies with nc; it cannot upgrade UDP into exactly-once delivery. Default CI fails on ambiguous actions, while an optional fresh session is a separately reported recovery experiment, never evidence that the earlier command executed correctly.

## Primary sources and limits

- [Official RetroArch Network Control Interface](https://docs.libretro.com/development/retroarch/network-control-interface/), accessed 2026-10-13: UDP endpoint, nc example and replies to sender, GET_STATUS status/content shape, GET_CONFIG_PARAM supported names, READ_CORE_MEMORY descriptor errors, LOAD_STATE_SLOT response, action/button names. Current docs are advertisement, not proof of 1.22.2 binary support or completion timing. They expose no request-ID or deduplication contract. A reply to a read is not an acknowledgment of a preceding action.
- [IETF RFC8085 section 3.3](https://www.rfc-editor.org/rfc/rfc8085.html#section-3.3), March2017, accessed 2026-10-13: UDP may lose, duplicate, delay or reorder packets, including across sessions; no well-defined maximum delay. Consequently neither a sleep nor a read response establishes an ordering barrier. This is design reasoning applied to the harness, not a new host protocol requirement.

No external source wording is quoted. Protocol capability and causality claims above are deliberately bounded. No new support was runtime verified during discussion.

## Command classification matrix

Policy classification is an inference from the owned sequence and external transport semantics. Support column separates documentation from historical evidence; implementation must validate only approved existing behavior against the pinned released binary.

| Command | Support status | Retry classification | Required confirmation / warning |
|---|---|---|---|
| GET_CONFIG_PARAM savestate_directory | Documented supported name; historically used on pinned binary | Read-only bounded retry | Exact echoed name and expected epoch-specific path; readiness only, not machine state/action completion |
| GET_STATUS | Documented; historical 1.22.2 crash | Research gate; exclude default harness | Only reconsider in isolated pinned-binary capability check; crash is explicit gate failure; paused/playing does not count frames |
| READ_CORE_MEMORY | Documented descriptor-based query; adapter advertises no descriptors | Research gate; exclude default harness | Descriptor errors/unsupported never count as anchors; do not add memory map just to use command |
| READ_CORE_RAM | Documentation requires achievements addressing; not established for this build | Research gate; exclude default harness | Do not substitute achievement addresses for a verified current oracle |
| PAUSE_TOGGLE | Historical sequence use | Non-idempotent, one send | Observable stable paused condition plus distinguishable progression control; any uncertainty fails, no retry based on read reply |
| FRAMEADVANCE | Historical sequence use | Non-idempotent, one send | Exactly +1 in distinguishable fixture or valid absolute anchor; dropped/doubled/stale images must fail |
| REWIND | Historical paced burst and coarse movement | Non-idempotent, fixed planned sends, no replacement retries | Burst is one logical operation with pre/post anchored movement and finite count; no exactly40 proof unless oracle supports it |
| RUNAHEAD_TOGGLE | Historical paused use | Non-idempotent, one send | Approved load/advance display-offset relation; unknown config param is not verification; failure ends attempt |
| SAVE_STATE | Historical save at pause/rewound point; measured ineffective after frame advance | Conditional idempotence only | Fixed slot, confirmed stable underlying state, no auto-slot change, fresh file/container/anchor; late repeated writes must not cross into progression. Preferred conservative default one send, bounded file polling |
| LOAD_STATE_SLOT 0 | Documented response; historical pinned paused load | Conditional idempotence only | Immutable known state, fixed slot, paused machine; echoed slot is receipt, not completed restoration. Historical paused load does not redraw: confirm the planned load + one advance compound against saved-anchor+1; no resend while confirming |
| LOAD_STATE | Documented button; historical bare load ignored paused | Exclude existing sequence | Preserve explicit-slot operation; no retry workaround |
| SCREENSHOT | Historical file output | Conditional idempotence only | Same stable capture target and phase; unique expected new path, completed decodable image, no pending earlier captures. Prefer one send + bounded polling; retries create ambiguity if delayed requests cross phase boundaries |
| QUIT | Historical one-send configuration | One send; no blind double-QUIT | Original launched process reaped, required exit status, bounded cleanup; killed timeout is failure, never successful graceful quit |

Conditional idempotence is a property of the entire controlled interval, not the command spelling. SAVE_STATE issued twice while frames run writes different states. LOAD_STATE issued late after FRAMEADVANCE erases progression. A delayed SCREENSHOT from a previous phase can capture the next phase and be wrongly renamed. Strict default permits retries only of reads; save/load/screenshot retries require a demonstrated closed-phase completion mechanism on the pinned binary, and absent that mechanism remain one-shot. This still exercises EVID-02 safely retried requests without pretending every mutation can be made safe.

## Closed-loop failure and epoch policy

1. Allocate a unique attempt directory and isolated configuration, home, screenshot and state paths, record core/content/version hashes, and own one launched process. Check content identity and command endpoint ownership. Default55355 should be serialized and collisions must fail, not connect to another host. A new server port per restarted epoch prevents old delayed action packets reaching the replacement process; a new directory alone does not. This changes an existing test config value, not protocol or host features.
2. Establish readiness through exact GET_CONFIG_PARAM path and launched-process liveness. Use epoch-specific path value to reject an old session reply. Reply sockets should not reuse retired local ports during the attempt if strong stale-read rejection depends on endpoint isolation; ordinary nc ephemeral allocation does not promise this. A helper can reserve retired sockets or otherwise enforce this narrow policy. Do not invent a nonce that the server does not echo.
3. For each logical action, record its before anchor, send count and expected postcondition. Send once, poll observation within both per-command and overall deadlines, check launched-process liveness, and close that step before next unrelated state-changing command. The existing pinned host records that LOAD_STATE_SLOT while paused does not redraw; its confirmation may therefore be the explicit compound operation LOAD_STATE_SLOT 0 + one FRAMEADVANCE, checked as saved-anchor+1. That advance is a planned discriminating probe, sent once; it is not a retry or separate already-proved load. Journal the compound boundary and never claim restoration was observed before the advance. Read-only retries may continue polling but do not resend the action. Reads accepted by grammar/endpoint are observations; no general happens-before relation is inferred.
4. Artifact completion means new exact identity, valid finished format and required state/frame relation. Existence/mtime/checksum change alone is insufficient. Prior/extra images or states remain quarantined and logged. A file path with a timestamp is not a protocol request ID. If delayed pending commands cannot be excluded at the phase boundary, fail conservatively.
5. Default: first ambiguous non-idempotent command fails the attempt and CI; retain artifacts, stop/reap owned process within cleanup budget. Do not treat QUIT timeout and forced kill as success. Do not replace an uncertain PAUSE_TOGGLE/FRAMEADVANCE with a presumed corrective repeat.
6. Optional future fresh restart: hard cap one complete fresh attempt, new process/directory/server endpoint, no resume from ambiguous checkpoint, retain both journals. CI should remain failed if an ambiguity occurred; a successful second attempt is diagnostic recovery evidence, not a green pass. Change this only with explicit future policy approval, measured flake and visible recovered classification; never silently loop until green.

Because the protocol has no action IDs/deduplication or general completion barrier, arbitrary unseen delayed duplicates cannot be ruled out universally. The claim is bounded, attributable evidence under the tested local session assumptions, with rejection of observed contradictory/ambiguous outcomes. A network framework cannot fix a missing server-side guarantee.

## Budgets and diagnostics

Use one absolute monotonic overall deadline; each command's deadline is min(overall remaining, class budget). Initial design targets may reuse stated readiness30s, observation5s, quit10s, but those are proposals to measure on CI, not observed suitable budgets. Include subprocess launch/receive/poll/decode time; counters×sleep omit nc and filesystem latency. Keep outer CMake150s only after measuring total success and failure bounds including cleanup; update workflow timeout comments from measured hosted runs as project policy requires. An independent parent timeout remains the final guard if shell stalls.

Small-helper trigger: shell cannot provide reliable monotonic/receive deadlines and reap behavior with installed tools. Helper would be test-only POSIX sockets/poll/monotonic time and exact bounded replies; no cross-platform host expansion, library transport or dependencies. Prefer exposing transport as one owned script function and a narrow fake-peer test seam, not a command DSL or generic retry framework.

Journal records: epoch, step, command class/name, attempt/send ordinal, elapsed monotonic time, deadline, expected/postcondition result, parsed reply or sanitized malformed excerpt, artifact relative path/hash, process exit and reason (unsupported/transport/timeout/liveness/oracle/ambiguous). Never log environment dumps, personal config, arbitrary user paths, private ROM bytes or shell-expanded credentials. Sanitization substitutes build, home and workspace prefixes and rejects unsafe symlinks; retained ROM is only approved manifest content if explicitly needed, normally record fixture hash instead.

Failure bundle: journal, sanitized generated config, pinned host/core/fixture hashes and build revision, parsed anchor results, raw/converted test screenshots, owned generated states and host log, outcome manifest, reproduction command with relative paths. Upload on every failure including startup/timeout; preserve partial images diagnostically and recheck privacy before upload. Use explicit finite retention (proposed14days, adjusted to repository policy if present). Keep attempt directories separate; a retry must not overwrite first failure. Existing artifact upload globs need include these artifacts plus command history and cfg/manifest, and preserve parent timeout output.

## Minimal automated test contract

Use a focused fake endpoint/transport seam and scripted artifact/oracle outcomes, plus real pinned-host happy path. All are future verification proposals, not executed results. Offline controls belong in `cmake --workflow --preset ci`; hosted binary capability/path remains existing macOS e2e job.

- Drop one read-only readiness request: bounded retry recovers, exact reply accepted; wrong name/path/malformed/empty response does not.
- Drop FRAMEADVANCE or PAUSE_TOGGLE: deadline terminates with one action send, nonzero outcome; no next action. Replay a helper mutant that blindly retries to show control fails it, rather than simply asserting a constant send count.
- Execute FRAMEADVANCE but lose its observation response: ambiguity fails without second advance; late valid outcome before deadline may confirm if uniquely tied to same step, after deadline cannot resurrect success.
- Duplicate/delay advance, toggle or load across phase boundary: distinguishable oracle rejects extra frame, wrong pause or overwritten restored anchor; do not let a stale screenshot satisfy next tag.
- Matching-shaped stale read response from old socket/epoch, wrong peer, old savestate_directory: reject or classify ambiguous; test endpoint isolation rather than claiming token-based correlation absent from protocol.
- SAVE_STATE/file exists before send, partial file, wrong slot, unchanged/wrong frame and writer completing after timeout: no pass. Stable conditional retry is accepted only if the implementation's completion rule is demonstrated; otherwise test forbids resend.
- SCREENSHOT old image, extra image, empty/truncated PNG, delayed earlier screenshot: reject/retain evidence; a single dropped screenshot fails under default one-shot policy.
- GET_STATUS unsupported/crashing capability and READ_CORE_MEMORY descriptor error: explicit research gate, no silent fallback to weaker proof or skip.
- Process exits during readiness/command/poll, no response, nc failure/hang, filesystem poll failure: bounded failure and full cleanup. QUIT sent once, timeout+kill stays failed.
- Overall deadline expires while per-command budget remains; nested nc timeout consumes budget; cleanup bounded. Test with deterministic clock seam where possible and one short wall-clock integration to prove stalled-child bounding.
- Fresh diagnostic attempt uses new process/port/directory; old queued datagram cannot affect new epoch; first failed report retained and aggregate CI remains failure. No success-by-retrying test ambiguity.
- Closed-loop trace: unrelated action n+1 is absent until n's postcondition succeeds; explicitly modeled load+single-advance compound may use the advance as its probe; read replies alone do not unlock action n+1; EVID-01 dropped/doubled/wrong-load/identical-image controls use the same oracle as happy path.

## Footguns and change triggers

Do not treat nc exit0 as host execution; do not use configuration read as action fence; do not parse arbitrary nonempty responses. No PAUSE setter appears in documented interface, so avoid inventing one. Sleeps pace commands but are not completion proofs. A fresh process needs endpoint and artifact epoch separation. STATUS support must not be assumed because docs are current. READ_CORE_MEMORY would require separate supported memory-map work; it is not Phase16. Save bytes/checksum may match legitimately and snapshot completion may lag. Rewind coarse bound proves rewind occurred, not receipt/exact execution of every planned REWIND. Screenshot identity needs EVID-01 adversarial oracle, not an existential match among repeated pictures. Do not add general ACK logic, vendored sockets libraries, protocol replacement or perfect-reliability claims.

Promote helper only after a minimal shell control fails a demonstrated deadline/attribution need. Revisit pinned host support on deliberate host upgrade, with isolated capability crash checks and regenerated measured offsets. Consider full-session restart only after measured recurring environmental failures and explicit result policy. If no existing fixture/state anchor can confirm the closed loop on the pin, feed this evidence to the EVID-01 fixture choice instead of weakening acceptance.

If the prototype cannot provide a discriminating boundary, fail that design and adjust the owned fixture/oracle within EVID-01/02 rather than weakening the claim.
