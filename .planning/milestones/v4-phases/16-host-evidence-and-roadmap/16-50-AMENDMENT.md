## Substantive proposed remedy: acyclic exact-byte closure

The following is the required design for a future executable plan set after
the scope boundary is resolved. It replaces whole-proposal compression and
recursive receipt embedding. Renumbering Plan48's failing emitter, merely
switching compression, increasing a bound or omitting original bytes is not
this remedy.

1. Freeze exact prospective producer, independent receiver, byte codec,
   request builder, A/B program, partitioner, journal encoder, comparator and
   literal expected-case table sources before the first actual prospective
   call. Bind their exact UTF8 lengths/SHA256 to the actual parent/executor
   closure. Keep source, exact submitted request and untouched complete actual
   returned object as distinct typed records. Preserve field absence and all
   exposed session/poll/stream/error/metadata fields, not a selected output
   string. The complete actual object is immediately retained before parsing
   or presentation. Provider-created hidden fields remain unavailable.
2. Retain each distinct exact original byte object once in the independent
   receiver's private machine store. Object identity binds kind, origin case,
   exact byte length and SHA256. SHA equality alone does not establish actual
   reception: the original awaited result/request and complete actual byte
   material must already exist under the matching immutable key. A later
   reference can name only an earlier independently received object or a new
   literal byte leaf carried by the current actual returned frame.
3. A B result describes its new outcome, exact I/C deltas and proposed receipt
   with a finite ordered byte recipe. Each piece names a checked earlier
   original's byte range or supplies new literal bytes. Reconstruct the
   complete receipt/proposed target bytes in receiver-private memory and
   compare them byte-for-byte with an independently derived expected result.
   Validate every range, order, length and referenced origin, and the whole
   reconstructed identity. The recipe is lossless serialization of already
   received bytes; it is never evidence that an unreturned byte was received.
   Reject missing references, foreign-case splice, forward/self reference,
   cycles, ambiguous duplicate keys, overlap/gap, wrong bounds and coherent
   changed bytes for their intended reasons.
4. Do not put the whole serialized A request/result, full P, full B proposal or
   accumulated previous receipts back inside each new B result. The full
   actual A remains retained once, and B consumes that complete actual A
   independently. Its output references the already retained exact original

   changes the wire representation of the prior full-A-in-B duty; it preserves
   full actual A validation and exact receipt reconstruction. No referenced
   byte may be synthesized from a model transcript, expected output, producer
   memory handle, filesystem path or digest alone.
5. Keep P, I, J_A=P+I and J_B=J_A+C separate. Retain complete original P and all

   perform actual byte comparison. B checks current bytes equal J_A, appends

   Receiver independently reconstructs ALL canonical snapshot bytes from
   actual READ returns and byte-compares a second actual COMPARE stream;
   canonical UTF8/JSON is checked after complete byte joining, including LF.
7. Bound each frame's complete serialized metadata, range cardinality, literal
   lengths, output and error form in advance. Measure uncompressed worst-case
   base64 framing, including LF and stderr. Compression may reduce size, but
   cannot be the capacity argument or rescue a failed dispatched source.
   Compute a strict per-result reachable closure bound counting each distinct
   reconstructed byte object once, including source/request/journal material.
   The entire snapshot may span many results; no single result can evade the
   decoded cap by expanding an oversized dependency closure. References to
   retained cumulative state do not claim that whole state was returned anew.
8. Every actual packet follows await original result → immediate immutable
   original retention → independent validation/reconstruction → receiver
   commit → bounded complete model-visible receipt → separate ACK → producer
   cursor advance. At most one packet is outstanding. No background/fanout
