## Recommendation and confidence

Propose a four-phase milestone, **Reliable supported-NTSC execution**: selected cartridge/admission corrections; generated-ROM execution safety; trustworthy existing RetroArch checks; a bounded conformance slice and release. Each phase should deliver a useful tested increment. Regional support, broad GUI-host coverage and speculative optimization should remain separate candidates. This recommendation complements the hardware researcher's prioritization: replace the conformance slice with the highest-value documented NTSC failure if its discovery gate supplies stronger evidence.

## What is already proved, and what is not

The v3 audit records all 18 requirements satisfied and identifies three substantive Phase13 test warnings (`.planning/milestones/v3-MILESTONE-AUDIT.md:1`). They remain observable: screenshot sets admit multiple possible frame numbers, `ra_chain` advances a surviving candidate chain, and the final saved state is checked without anchoring its frame (`tests/retroarch/run_retroarch.cmake:571`, `:648`). A dropped FRAMEADVANCE can leave an identical picture and still fit the next member of an ambiguous pair. The script sends most actions once while retrying only the second SAVE_STATE (`tests/retroarch/state_session.sh:110`, `:163`). Full-path substring matching still selects special ROMs (`tests/libretro/libretro_host.c:2029`, `:2395`; `tests/core/test_state_runahead.c:130`). These are current test-evidence weaknesses, not proof that released state emulation fails.

Conversely, six-platform state/frame/audio equality and portable libretro run-ahead tests already exist (`README.md:592`, `:1393`). The old v2 MMC3 hosted save gap was subsequently closed (STATE's Phase11 note). The old state-fuzz timeout placeholder is obsolete: nightly now cites sampled histories and uses four minutes (`.github/workflows/nightly.yml:236`). Phase15 performance and inherited-SIG_IGN warnings are fixed; do not charge the next milestone for them. Failed-create zero AV info is low value because successful content load refuses a NULL instance and official AV queries follow successful load (`libretro/libretro.c:295`; [core-development contract](https://docs.libretro.com/development/cores/developing-cores/)). Comment wrapping, duplicate small helpers and historical metadata repairs do not justify a cleanup phase.

Execution coverage needs accurate wording. Loader fuzz loads/unloads but never runs (`tests/fuzz/rom_loader.c:17`). State fuzz executes two frames after accepted mutations, using twelve synthetic board configurations (`tests/fuzz/state_loader.c:27`, `:175`, `:251`); it is not a general evolving-ROM program campaign. The main run loop is bounded by emulated ticks unless a CPU step or catch-up path fails to progress (`src/frame.c:52`). A game looping forever in software is normal and must still return frames. Security risk is an emulator memory defect, resource exhaustion or failure to return—not native execution of NES instructions. No exploit or hang was demonstrated in this research.

## Four proposed phases and stakeholder tradeoffs

**1. Supported-content truth and selected defects.** Players gain correct behavior or honest rejection; host integrators gain trustworthy metadata; the C architect avoids broad board abstractions; provenance reviewers get hardware citations. Reproduce the old MMC1 submapper5 and reset/mirroring questions before accepting their audit wording: submapper5 is still admitted only at a constrained PRG size (`src/cartridge.c:108`), but the hardware researcher owns determining correct behavior. Concrete host fix: `.info` description omits MMC3 even though mapper4 runs (`libretro/nesturbator_libretro.info:24`). A directory at a save path still reaches `ftell`/size classification (`runner/save.c:66`), warranting a platform reproduction before changing its documented exit. Strongest alternative: reject unsupported subprofiles and publish precise limits; prefer that over speculative mapper behavior. Cost M; prerequisite source-backed minimal repro. Exit: every chosen defect has a failing owned test, corrected behavior/rejection, README/header updates, CI workflow pass, and explicit review disposition. Cap to a few product defects; no all-debt sweep.

**2. Deterministic execution robustness.** Security and test engineers get runtime reach; maintainers accept modest CI cost; performance engineers retain production paths. Build one owned C harness from input bytes: select an accepted board profile, derive bounded PRG/CHR bytes, execute a small fixed frame budget with controlled input, then reset/save/load/unload/reload. Keep raw loader fuzz separately. Ordinary infinite NES loops must return frames; JAM is an expected stop. Compare independent instances and save/load continuations; use sentinel buffer guards, sanitizer checks and documented statuses, not a hardware-correctness oracle. Strongest alternative: merely run accepted raw fuzz images; cheaper, but rejection dominates and large banks receive poor exploration. Cost M; prerequisites existing harness/build wiring and a throughput/coverage baseline. Exit: every supported mapper reaches execution and register paths, deterministic corpus replays run in normal CI on supported platforms, nightly ASan/UBSan has bounded time/RSS and retains reproducible failures. Discovery gate: one short campaign first; measure accepted inputs, execution coverage and slow seeds before choosing budgets. LLVM recommends fast deterministic targets and supplies timeout/crash artifacts ([libFuzzer](https://llvm.org/docs/LibFuzzer.html)); UBSan catches signed overflow and invalid shifts, but does not prove hardware correctness ([UBSan](https://clang.llvm.org/docs/UndefinedBehaviorSanitizer.html)). Reuse existing libFuzzer despite maintenance-only status; switching engines adds no demonstrated project value.

**3. Trustworthy RetroArch proof.** Test engineers eliminate false evidence; devops trades a small scripting change for less flake; integrators retain one real-host reference. Anchor chains against known saved frame numbers and add negative fixtures for dropped/doubled advances and wrong loads. Preserve possible identical-picture ambiguity honestly; reject an unprovable assertion rather than inventing certainty. Retry idempotent SAVE_STATE and screenshot requests with bounded confirmation; never blindly retry FRAMEADVANCE or PAUSE_TOGGLE. Confirm pause status if the pinned binary supports it; current official NCI documents GET_STATUS, but this requires a binary capability probe ([NCI](https://docs.libretro.com/development/retroarch/network-control-interface/)). The existing script's per-loop/drop behavior is T3 pinned-host evidence. Match fixture basenames, with adversarial parent directory names. Strongest alternative: replace visual frame identity with an owned synthetic frame-marker fixture; select it if state anchoring cannot distinguish the tested sequence. Cost M; prerequisite strengthened local fixtures before hosted run. Exit: injected wrong sequences fail, safe requests recover from one loss, unsupported host commands fail clearly, repeated hosted runs retain states/logs/screenshots and meet measured deadlines.

**4. One conformance gain and closeout.** Players value real correctness; test/provenance engineers require independent evidence; devops needs bounded jobs. The AccuracyCoin scoreboard has 17 entries across pages2/14/17, not all144 tests (`tests/accuracy/scoreboard.txt:1`; preparation `CONFORMANCE.md:28`). Full 65x02 vectors and MMC3 public oracle lanes already exist (`.github/workflows/nightly.yml:57`, `:149`). Inventory existing registered tests and discover selected omitted CPU/DMA/PPU results before promising gains. Strongest alternative: add all public ROMs at once; reject because licenses, reporting protocols, hardware variants and unknown failures multiply scope. Cost bounded M; prerequisite the admission fixes and a short baseline report. Exit: one coherent supported subsystem gains named independent tests, explicit pass/fail/unsupported outcomes, preserved prior passes, six-platform equality, CI and release artifacts. Reference binary disagreement is T3 evidence; hardware docs and public test behavior resolve it. Test-source licenses and approved manifests remain mandatory; download nothing during this research.

## Rolling near, mid and long candidates

**Near:** regional milestone with PAL first and independently selectable Dendy. This is a real feature gap: NES2 byte12 must be zero, iNES bytes8–15 must be zero, and state region is fixed NTSC (`src/cartridge.c:174`, `:194`; `src/state.c:430`). Merely returning PAL from libretro would run wrong clocks/audio. Cost L; prerequisite region-specific timing fixtures and state-format design; exit exact rates, CPU/PPU/APU/DMA timing, video/emphasis, save/load and host metadata agree. Alternative stay explicitly NTSC; adopt until tests justify expansion. A plain `--capabilities` preflight is another near candidate only if a launcher needs it: mapper number alone cannot describe supported subprofiles. Cost S–M; exit capability output and load rejection share tested facts. Avoid a new shared multi-core ABI or schema framework.

**Mid:** one Linux real-RetroArch pilot after current evidence is reliable. Integrators gain loader/config coverage; devops pays binary packaging/display tooling costs. Alternative portable host matrix is already strong. Cap pilot to one session and supported pinned binary; promote only after a reproducible platform difference or concrete distribution requirement. Optimization likewise needs a measured target-machine frame/run-ahead budget and profile. Existing reproducible instruction-count gates (`15-PERF-PROOF.md:18`) detect regressions, not real-time CPU headroom. Exit unchanged correctness hashes plus measured improvement on the target; avoid skip-render/state shortcuts without proof.

**Long:** achievements memory descriptors and netplay only with an actual consumer acceptance test. `memory_descriptors=false` is truthful; no NETPLAY e2e is claimed (`README.md:1405`). Costs L, prerequisite stable state/region contracts; exit real consumer session and documented supported limits. Strongest alternative retain current three deliverables. Decline GUI/device code, general test frameworks, speculative JIT/threading, new dependency wrappers and wholesale helper deduplication.

At each milestone refresh these candidates with changed evidence, cost and dependency; Immediate remains empty until approval. Preserve distinct fields for current gap, proposed scope and verified completion.

## Adversarial synthesis pass: proposed v4

Read both sibling reports on 2026-10-13. **NTSC conformance and execution safety** is coherent if its promise is measured evidence and bounded robustness, rather than an unnamed accuracy-fix cluster. The strongest counterargument is that a baseline and a safety harness are developer infrastructure with uncertain visible player benefit; PAL supplies immediate compatibility. Nevertheless, the new AccuracyCoin pin introduces a decoder migration and new DMA probes, while runtime fuzzing independently exercises accepted content. Both produce durable, verifiable deliverables without promising a bug count. Near should follow measured gameplay-relevant NTSC defects, or PAL when remaining failures are narrow or revision-sensitive.

**Prefer four small phases:** (16) scoped evidence repairs and roadmap procedure; (17) AccuracyCoin pin/decoder/full baseline; (18) generated-program execution safety; (19) cross-deliverable evidence and release. A three-phase plan is defensible if closeout is a short final plan under phase18, but mixing fuzz development, host-halt policy and release makes its outcome harder to assess. The fourth phase is validation, not another opportunity to add features. Phase16 must enumerate the three Phase13 warnings and MMC3 metadata correction; defer unrelated save errors, mapper corrections and old info findings unless measurement establishes a concrete blocker.

**Ordering:** existing RetroArch evidence repairs can go first because they are already located, independent of the new conformance baseline, and protect later closeout claims. Limit this tune-up to those named repairs and the short rolling-roadmap procedure; no new roadmap checker. The full baseline must precede any accuracy-repair promise. Generated execution fuzz does not technically depend on conformance completion; sequential ordering merely keeps the milestone understandable. Gate a decoder/pin migration separately from hardware fixes: malformed-table cases fail, the new pin reports all146 tests plus five excluded DRAW entries, and every old protected key is mapped or explicitly accounted for. Each test receives pass/fail/skip/not-run/timeout with retained bytes and deadlines; an all-pass result is unnecessary.

**Identical pictures defeat naive negative controls.** Injecting dropped/doubled commands proves nothing if the captured pixels are indistinguishable and candidate-set membership still passes. Require an absolute state-frame anchor plus global sequence constraints; if ambiguity remains, use an owned deterministic unique-frame-marker fixture for exact advance tests. Validate that the fixture distinguishes every checked frame before running the host. Keep screenshots from existing games as compatibility evidence without claiming exact progression where unobservable. Negative fixtures must include both identical-image ambiguity and impossible anchored sequences. Retry only screenshot/save requests with unambiguous bounded completion; delayed screenshot arrivals must not be assigned to the next step. FRAMEADVANCE and PAUSE_TOGGLE require confirmation or fail/restart, never blind retry.

**Safety completion is finite:** replay every fixed corpus seed, execute every accepted board profile, demonstrate measured execution-path reach, retain sanitizer/timeout artifacts, and complete an explicitly capped nightly campaign with no unresolved reproducible safety failure. No promised discoveries and no claim that zero findings proves universal safety. Newly found blockers receive minimized deterministic reproducers; excessive findings trigger rescoping/splitting, not indefinite fuzzing. JAM discovery checks library stop/reset/state behavior and actual host callback behavior. The current adapter suppresses video on JAM despite the official once-per-run contract; document and test the chosen adapter policy if confirmed. This is host readiness, not evidence of a security exploit or a reproduced RetroArch hang. Keep owned C/CMake/libFuzzer and existing CI dependencies throughout.
