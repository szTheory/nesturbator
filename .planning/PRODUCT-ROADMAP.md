| Horizon | Meaning | Planning depth |
|---|---|---|
| Immediate | Current approved workstreams, which may be blocked independently | Requirements, executable phases and automated acceptance |

### LibFuturo check-in and migration method

At each new-milestone and complete-milestone review, compare the current LibFuturo roadmap, provider contract, and consumer evidence with Nesturbator's released capabilities. Use a current checkout when accessible or a fresh owner-supplied report when it is not; dated plans and old profile pins are context, not the target. Record what is verified, planned, blocked, and owned by each repository. Promote a standalone Nesturbator migration slice only when it closes a high-value Nest-owned gap. Otherwise, carry the consumer profile into the most relevant general emulator milestone and retain the decision history, so future reviews do not rediscover the same ground.

### Remaining NTSC accuracy clusters: Proposed follow-on choices

After the full baseline, prioritize named game-relevant failures before obscure score points. The five-row NTSC DMA cluster shipped as RM-016 in v7; those rows now pass at the unchanged pin. `DMA + $4015 Read`, `Misaligned OAM DMA` and `INC $4014` remain protected regression guards. The bounded Phase 21 DMC retry/open-bus repair was a prerequisite, not completion of this cluster. The exact causal relationship among the original failures remains documented in the v7 evidence. Do not require an affected-title claim without evidence; DMC/controller corruption is only a relevance lead. Other clusters below remain uncommitted and each needs its own approval.
- Sprite evaluation/OAM: `Sprites On Scanline 0`, `Stale Sprite Shift Regs`, `Frozen OAM2 Increment`, `Misaligned OAM2 Address`, the `$2004` rows, `Misaligned OAM behavior` and `OAM Corruption`. Both previously not-run rows now terminate as FAIL; `Suddenly Resize Sprite` already passes.
- PPU rendering reads: `$2007 Stress Test`, `Stale BG Shift Registers`, `BG Serial In`, `ALE + Read`. Other `$2007` rows and `Rendering Flag Behavior` already pass.
- CPU bus: open bus, internal data bus, `Hybrid Addresses`, `APU Register Activation`, `Controller Strobing`, and the five unstable `SH*` stores (last, since games rarely depend on them).

Hardware fixes need owned reproducers, documented hardware behavior, external test evidence and save-state coverage if instance fields change. ## Refresh procedure

At each new-milestone and complete-milestone step, the agent reads this file, project state, the last audit, seeds, release evidence, and current LibFuturo direction/evidence. It reconciles shipped/partial/parked items, refreshes each promotion trigger, records changed ordering and presents a preferred next milestone with alternatives. The LibFuturo check uses a current checkout or fresh owner-supplied report, distinguishes current evidence from plans, and promotes only concrete Nesturbator-owned gaps. If there is no standalone high-value migration work, retain the provider profile and integrate relevant checks into ordinary accuracy, mapper, region, or release work. This is part of the invoked step, with no extra lifecycle command or manual reminder.

After scope approval, promote selected IDs to Immediate/committed and link requirements/phases. At closeout, mark only evidenced outcomes shipped, keep real debt visible, refresh the remaining horizons and archive the agreed direction with that milestone. A newly reconstructed boundary snapshot must say when it was reconstructed. Phase discoveries change the ledger only when they affect direction, prerequisites or acceptance.

Keep the file small. Use existing Markdown and git; no roadmap service or parser dependency. A structural validator is optional if omissions recur; it cannot prove that priorities were reconsidered. Small owned helpers and justified local duplication are preferable to extra dependency trees, within the repository's ownership and clean-room rules.

## Why this shape

A separate product ledger preserves direction while GSD rewrites and archives execution phases. Seeds alone lack current ordering; mixing speculative horizons into execution phase headings invites accidental promotion. GitHub distinguishes exploratory direction from work selected for delivery, and Rust separates broad roadmaps from concrete goals. These practices inform this project's smaller readiness horizons rather than importing dates or governance machinery.
