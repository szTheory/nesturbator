### Why this design and strongest alternative

The concrete old-driver regression demonstrates why shell identity-check-plus-rm cannot deliver the existing foreign-object invariant (D-07 tools first; D-09 narrow owned test-only assistance only after demonstrated need). Existing Perl already supplies timer/journal/process evidence; a small inline use of bundled platform socket operations avoids a new native helper/build contract. Executor preflight must prove Socket/Fcntl are bundled and available on each affected installed test consumer; missing facilities stop incomplete, with no install or hidden dependency addition. Planning checked the existing UNIX-only registration and Perl callers, not every remote runner's installed module set.

Persistent flock is the strongest alternative: existing platform file locking and descriptor release are compact, but a replaced/unlinked lock pathname permits two live inodes and splits exclusion. An owner-only directory prevents other UIDs from mutating it but permits same-UID replacement; neither alternative meets the requested concurrency invariant without a stronger external lifetime/ancestor trust contract. Renaming then validating can already damage a foreign pathname; no foreign rename is permitted. A compiled socket helper could implement the selected mechanism but would add an executable/build/integration surface without a demonstrated need beyond the existing interpreter. Stop for amendment if Perl/descriptor semantics cannot be proven; do not silently switch architecture.
