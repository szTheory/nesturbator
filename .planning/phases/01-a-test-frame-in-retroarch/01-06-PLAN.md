1. Top-level CMakeLists.txt, using GNUInstallDirs and CMakePackageConfigHelpers (built into CMake):
   - `install(TARGETS nesturbator EXPORT nesturbatorTargets ARCHIVE DESTINATION ${CMAKE_INSTALL_LIBDIR} COMPONENT library)`;
   - `install(FILES include/nesturbator.h DESTINATION ${CMAKE_INSTALL_INCLUDEDIR} COMPONENT library)`;
   - `install(EXPORT nesturbatorTargets NAMESPACE nesturbator:: DESTINATION ${CMAKE_INSTALL_LIBDIR}/cmake/nesturbator COMPONENT library)`;
   - `configure_package_config_file(cmake/nesturbatorConfig.cmake.in ...)` and `write_basic_package_version_file(... COMPATIBILITY SameMinorVersion)`, both installed to the same directory;
   - `configure_file(cmake/nesturbator.pc.in ...) @ONLY`, installed to `${CMAKE_INSTALL_LIBDIR}/pkgconfig`. Use `${pcfiledir}`-relative prefix lines so it is relocatable.
   - LICENSE is installed to `.` once per component (library, runner, libretro). THIRD-PARTY-NOTICES.md goes to the libretro component.
2. `runner/CMakeLists.txt`: `install(TARGETS nesturbator-run RUNTIME DESTINATION bin COMPONENT runner)`. `libretro/CMakeLists.txt`: `install(TARGETS nesturbator_libretro LIBRARY DESTINATION cores RUNTIME DESTINATION cores COMPONENT libretro)` (RUNTIME covers the Windows DLL) and `install(FILES nesturbator_libretro.info DESTINATION info COMPONENT libretro)`. Exclude the host tool `palgen`, the `nesturbator_host` library and the tests from every install.
3. `cmake/nesturbatorConfig.cmake.in`: `@PACKAGE_INIT@` plus include of nesturbatorTargets.cmake.
4. `tests/consumer/CMakeLists.txt`: cmake_minimum_required 3.25, `project(consumer C)`, C17 extensions off, `find_package(nesturbator CONFIG REQUIRED)`, `add_executable(consumer main.c)` linked to `nesturbator::nesturbator`. `tests/consumer/main.c` includes only `<nesturbator.h>`, `<stdint.h>` and `<stdio.h>`. It creates with NESTURBATOR_CONFIG_INIT, runs one frame into caller buffers (256*240 uint16, 1024 int16), checks frame_number == 1, destroys, and returns 0 on success and 1 otherwise, printing the status number on failure.
5. tests/CMakeLists.txt, per RESEARCH:
   - `install.stage`: `${CMAKE_COMMAND} --install ${PROJECT_BINARY_DIR} --component library --prefix ${PROJECT_BINARY_DIR}/stage`, FIXTURES_SETUP staged;
   - `install.consumer`: `${CMAKE_CTEST_COMMAND} --build-and-test` with source `tests/consumer`, binary `${PROJECT_BINARY_DIR}/consumer`, `--build-generator ${CMAKE_GENERATOR}`, and `--build-options -DCMAKE_PREFIX_PATH=${PROJECT_BINARY_DIR}/stage -DCMAKE_C_COMPILER=${CMAKE_C_COMPILER} -DCMAKE_BUILD_TYPE=${CMAKE_BUILD_TYPE} "-DCMAKE_C_FLAGS=${CMAKE_C_FLAGS}" "-DCMAKE_EXE_LINKER_FLAGS=${CMAKE_EXE_LINKER_FLAGS}"`, then `--test-command consumer`; FIXTURES_REQUIRED staged. Each flag variable is passed as one quoted argument so a value with spaces or an empty value survives. Forwarding the parent's flags means the consumer compiles and links the way the staged library was built: under `asan` (plan 07) the library carries sanitizer instrumentation, and without the forwarded `-fsanitize` link flags the consumer link fails on unresolved sanitizer runtime symbols;
   - under multi-config generators add `--build-config $<CONFIG>`.

Globbing only the current version means CPack's `_CPack_Packages` staging directory and zips left from an earlier version in a reused local build tree never count:

   - It fails, naming the first missing entry or the extra file. It is a script run after the workflow (the package step follows the test step), not a ctest.
