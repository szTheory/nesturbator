1. `version.txt` holds the single line `0.0.0`. The top-level `CMakeLists.txt` does the following:
   - `cmake_minimum_required(VERSION 3.25)`; read `version.txt` with `file(STRINGS ... LIMIT_COUNT 1)`; `project(nesturbator VERSION <that> LANGUAGES C CXX)`.
   - `CMAKE_C_STANDARD 17`, `CMAKE_C_STANDARD_REQUIRED ON`, `CMAKE_C_EXTENSIONS OFF`.
   - Warning flags in a function `nesturbator_warnings(target)` that applies:
     - GCC and Clang: `-Wall -Wextra -Wpedantic -Wshadow -Wconversion -Wsign-conversion -Wstrict-prototypes -Wmissing-prototypes -Wvla`;
     - GCC only: `-Wduplicated-cond -Wlogical-op`;
     - MSVC: `/W4`.
   - Core target `nesturbator`: STATIC, sources `src/instance.c src/frame.c src/testcard.c`, PUBLIC include dir `include` through `$<BUILD_INTERFACE:...>`/`$<INSTALL_INTERFACE:include>`. Properties: `C_VISIBILITY_PRESET hidden`, `POSITION_INDEPENDENT_CODE ON`, `VERSION ${PROJECT_VERSION}`, `SOVERSION 1` (D-07: SOVERSION equals the ABI number). Alias `nesturbator::nesturbator`. It links nothing.
   - Then `enable_testing()`, `add_subdirectory(runner)` and `add_subdirectory(tests)`.
2. `CMakePresets.json`, schema version 6, `cmakeMinimumRequired` 3.25:
   - Configure presets:
     - hidden `base`: generator Ninja, `binaryDir ${sourceDir}/build/${presetName}`;
     - `dev`: Debug;
     - `ci`: Release, `CMAKE_COMPILE_WARNING_AS_ERROR ON`;
     - `ci-msvc`: inherits `ci`, `CMAKE_C_COMPILER` and `CMAKE_CXX_COMPILER` set to `cl` (Pitfall 13).
   - Build, test and workflow presets for `dev`, `ci` and `ci-msvc`. Each workflow has configure, build and test steps; plan 06 adds the package step. Each test preset sets `output.outputOnFailure true` and `execution.noTestsAction error`.
3. `include/nesturbator.h` implements the `<interfaces>` block exactly:
   - Guards and `extern "C"` blocks; it includes only `<stdint.h>` and `<stddef.h>`.
   - Each version macro line carries its release-please marker comment (`x-release-please-major`, `-minor`, `-patch`).
   - `NESTURBATOR_CONFIG_INIT` is `{ (uint32_t)sizeof(nesturbator_config), NESTURBATOR_ABI_VERSION, { NULL, NULL, NULL } }`. Every member is listed, so neither C `-Wmissing-field-initializers` nor C++ narrowing fires (Pitfall 6).
   - Every function and struct gets a comment stating its contract:
     - the size-tag rules (input: reject 0 or below the first released size, accept larger only if the tail is zero; output: write min(size, sizeof));
     - "a failing call changes no state";
     - all-NULL allocator means malloc/free, partly NULL is ERR_ARGUMENT;
     - frame and sample rates as num/den;
     - "no cartridge: test pattern and silence".
4. `src/internal.h` declares:
   - the instance struct: allocator copy, `uint64_t frame_number`, `uint64_t ticks`, `uint32_t audio_rem`;
   - `NESTURBATOR_TICKS_PER_FRAME 714732u` (24 ticks per CPU cycle, ARCHITECTURE §2; 714732 matches the reported 39375000/655171, RESEARCH Open Question 1);
   - the first-released-size constants for each struct (equal to this build's sizeof);
   - the single size-tag helper `nesturbator__check_size_in(const void *s, uint32_t first, uint32_t ours)` per RESEARCH Pattern 1 (reads the tag with memcpy before any other field);
   - `uint16_t nesturbator__test_pixel(uint32_t x, uint32_t y)`.
   The core library holds no mutable static or global variable (ENGINEERING §1).
5. `src/testcard.c` implements `nesturbator__test_pixel` per D-01/D-02, first matching rule wins:
   - corner block rows 0–7 × cols 0–7 → 0x30;
   - border row 0, row 239, col 0, col 255 → 0x30;
   - rows 1–7 → 0x16; rows 232–238 → 0x12;
   - chart rows 8–231: b=(y-8)/28, r=((y-8)%28)/7, c=x/16, pixel = (r<<4 | c) | b<<6.
   All arithmetic is uint32_t, cast to uint16_t at return. Comment each rule with "D-02" and its purpose (mirror detection, flip detection). Per D-03, no version, ABI or text goes into the pixels: version information is reported by nesturbator_get_version (and later by retro_get_system_info and the .info file), so the recorded hash never changes with a release.
6. `src/instance.c`:
   - `nesturbator_get_version` and `nesturbator_get_info` (256, 240, 39375000/655171, 48000/1) write min(out->size, sizeof) bytes from a fully built local copy whose size field keeps the caller's value. A NULL out, or out->size 0, writes nothing.
   - `nesturbator_create` checks, in order:
     1. cfg/out NULL → ERR_ARGUMENT;
     2. size tag → ERR_STRUCT_SIZE;
     3. abi != NESTURBATOR_ABI_VERSION → ERR_ABI;
     4. allocator all-NULL → assign a static function pair wrapping malloc/free into the instance's allocator copy in code, with no file-scope `nesturbator_allocator` object or other table of pointers (under ELF PIC such a const table lands in `.data.rel.ro`, which plan 07's `abi.global_symbols` rejects); partly NULL → ERR_ARGUMENT;
     5. allocation failure → ERR_NO_MEMORY.
     `*out` is written only on success.
   - `nesturbator_destroy` accepts NULL and frees through the allocator with the size.
7. `src/frame.c` `nesturbator_run_frame` checks everything before mutating anything:
   - inst/io NULL → ERR_ARGUMENT; size tag → ERR_STRUCT_SIZE; video NULL → ERR_ARGUMENT;
   - video_pitch < 256 → ERR_BUFFER_TOO_SMALL;
   - audio count n = (audio_rem + 714732*352) / 315000 computed in uint64_t (RESEARCH Pattern 2);
   - audio NULL with audio_capacity > 0 → ERR_ARGUMENT; audio_capacity < n → ERR_BUFFER_TOO_SMALL.
   Only then does it:
   - write test_pixel for every pixel at video[y*pitch+x];
   - zero n samples;
   - set audio_count = n and audio_rem = acc % 315000;
   - frame_number += 1 (equals 1 after the first call, RESEARCH Open Question 2) and ticks += 714732;
   - copy frame_number and ticks into io.
8. `runner/sha256.h`/`runner/sha256.c`: own SHA-256 from FIPS 180-4 with an init/update/final API (`nesturbator_run_sha256_init`, `_update`, `_final`) and a hex helper. It uses no library. Its known-answer test arrives in plan 02; the tracer's end-to-end hash below already exercises it against an independent model.
9. `runner/main.c` (`runner/CMakeLists.txt` defines executable `nesturbator-run`, links `nesturbator::nesturbator`, gets `nesturbator_warnings` and the MSVC define `_CRT_SECURE_NO_WARNINGS`; no output-directory property is set, so with the single-config Ninja generator the runner builds to `build/<preset>/runner/nesturbator-run` (`.exe` on Windows), the same per-subdirectory layout as `build/<preset>/libretro/` in plan 05; every verify path in this phase uses that location, and tests use `$<TARGET_FILE:nesturbator-run>`):
   - Parse `--frames N` (default 0) and repeatable `--hash-frame N`. Any unknown option, a missing or non-numeric value, a ROM path argument (Phase 3), `--frames 0` or `--hash-frame 0` → usage message on stderr, exit 2. A hash-frame N > --frames is also usage exit 2. No arguments at all runs zero frames, prints nothing and exits 0.
   - Create one instance with NESTURBATOR_CONFIG_INIT and run N frames into a 256x240 uint16 buffer and an int16 audio buffer of 1024.
   - For each requested frame, hash the pixels as little-endian bytes (low byte first, written byte by byte, never by casting the buffer). Print `frame <N> ticks <ticks> sha256 <hex>` to stdout.
   - Exit 0 on success. A non-OK status from the core → message on stderr naming the status number, exit 1.
10. `tests/cmake/expect_output.cmake`: a `cmake -P` script taking `-DCMD=<;-list>`, `-DEXPECT=<exact expected stdout>` and `-DEXPECT_EXIT=<code>`. It runs CMD with execute_process, strips `\r`, and fails with FATAL_ERROR showing actual vs expected when the output or exit code differ. `tests/CMakeLists.txt` registers `runner.hash` running `$<TARGET_FILE:nesturbator-run> --frames 1 --hash-frame 1` and expecting exactly `frame 1 ticks 714732 sha256 b49e9be44573a4de82d845179d4389a0a6e28e934bd9ab31516a40db2c0b0453` plus newline, exit 0. That value comes from an independent Python model of D-02 (RESEARCH). If the C output differs, find which side misreads D-02 before changing anything.
