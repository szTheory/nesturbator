1. `tests/vectors/n65v.h` and `n65v.c`, the reader (D-03, D-05). Nothing core-side includes it.
   - Types: `struct n65v_state { uint16_t pc; uint8_t s, a, x, y, p; uint8_t ram_count; uint16_t ram_addr[255]; uint8_t ram_value[255]; }`, `struct n65v_cycle { uint16_t addr; uint8_t value; uint8_t kind; }` and `struct n65v_test { uint16_t index; struct n65v_state initial, final; uint8_t cycle_count; struct n65v_cycle cycles[255]; }`.
   - `struct n65v_reader` holds the buffer, length, offset, the expected first opcode, chunk count and tests per chunk, the current position, and `char error[160]`.
   - `void n65v_init(struct n65v_reader *r, const uint8_t *buf, size_t len, uint8_t first_opcode, uint32_t chunks, uint32_t tests_per_chunk)`.
   - `int n65v_next(struct n65v_reader *r, struct n65v_test *t, uint8_t *opcode)` returns 1 for a test, 0 at a clean end, and -1 on an error whose message starts with `offset <n>:`.
   - Little-endian, decoded byte by byte, never memcpy into a struct. Check bounds before every field as `n > len - off`.
   - At each chunk start it checks magic `N65V`, version 1, opcode equal to first_opcode plus the chunk number, and count equal to tests_per_chunk.
   - Index must strictly increase within a chunk. Kind must be 0 (read) or 1 (write).
   - The end must come exactly after the last chunk; trailing bytes are an error.
   - Every narrowing gets an explicit cast (Pitfall 4).
2. `tools/vecconv/vecconv.c` and its `CMakeLists.txt` (D-01, D-02).
   - The executable is `vecconv`, built from vecconv.c plus `${PROJECT_SOURCE_DIR}/tests/vectors/n65v.c` with a private include of `${PROJECT_SOURCE_DIR}/tests/vectors`. It gets `nesturbator_warnings`, MSVC `_CRT_SECURE_NO_WARNINGS`, and is not installed.
   - Usage: `vecconv <in.json> <out.n65v> <opcode-hex> [--first N]`. Anything else exits 2 with a usage line.
   - It reads the whole file, then tokenizes with a schema-specific tokenizer:
     - any JSON whitespace; keys matched by name: `name` (dropped), `initial`, `final`, `cycles`, `pc`, `s`, `a`, `x`, `y`, `p`, `ram`;
     - unsigned decimal integers only;
     - kinds `"read"` and `"write"` only.
   - It exits 1 with `vecconv: <in>: offset <n>: <reason>` on any of these: a float, a sign, an exponent, an address above 65535, a byte above 255, a list longer than 255, an unknown kind, an unknown or missing key, or a first cycle that is not a read of `<opcode>` at the initial pc.
   - With `--first N` it stops after N complete objects and ignores whatever follows; a prefix that ends inside the N-th object is an error. Without it the array must close with `]` (trailing whitespace allowed) and hold exactly 10000 objects.
   - It writes one N65V chunk. Index is the 0-based position in the file, and RAM pairs keep JSON order.
   - It re-reads the output through `n65v_init`/`n65v_next`, with 1 chunk, opcode `<opcode>` and the written count. It exits 1 if that fails.
   - On success it prints exactly `vecconv: <xx>: <n> tests written and re-read` on stdout, `<xx>` being the lowercase opcode.
   - Integer-only.
