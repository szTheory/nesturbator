Create tests/retroarch/log_check.cmake per D-28 as amended at planning. At file scope it defines only function nesturbator_ra_log_check(LOG ALLOWLIST LEVEL REQUIRE_NETCMD). The direct-run path is guarded by `if(CMAKE_SCRIPT_MODE_FILE STREQUAL CMAKE_CURRENT_LIST_FILE)`, true only when the file is the -P entry script; inside the guard it requires -DLOG and calls the function with -DALLOWLIST (default ${CMAKE_CURRENT_LIST_DIR}/log_allowlist.txt), -DLEVEL and -DREQUIRE_NETCMD. When run_retroarch.cmake include()s it, CMAKE_SCRIPT_MODE_FILE names run_retroarch.cmake, so the guard is false and nothing runs until run_retroarch.cmake calls the function. The header comment says what it enforces and why: the adapter requests no log interface, so a core RETRO_LOG_ERROR line cannot appear, and "no core error" (success criterion 3) is enforced by failing on any line-start-anchored `[ERROR]` line in RetroArch's own log. Allowlist parsing: lines starting with `#` are comments, blank lines are ignored, every other line is `<level><TAB><regex>` with level one of any, serialized, deterministic; an entry whose previous line is not a comment is a FATAL_ERROR. Matching: a log line is flagged when it matches `^\[ERROR\]` or `^\[(WARN|ERROR)\] \[(Rewind|Run-Ahead)\]`; a flagged line passes only if some entry with level any or equal to LEVEL matches it. Lines containing `Failed to save state` or `Failed to load state` always fail (no allowlist). With REQUIRE_NETCMD on, the absence of a line containing `[NetCMD]` fails. Collect every violation, print each as `un-allowlisted line: <line>` (or the failed-save/load or missing-NetCMD reason), then FATAL_ERROR once; on success print a STATUS line listing which allowlist entries were used.

Create tests/retroarch/log_allowlist.txt with a header comment describing the format and the rule that each entry is measured on RetroArch 1.22.2. Add further entries only for lines actually measured in this plan's lane logs (and Plan 07's), scoped to the narrowest level that shows them (for example a Run-Ahead warning seen only while the .info says serialized is scoped `serialized`, so it stops being allowed once deterministic is claimed); record every added entry and its measured lane in the SUMMARY.
