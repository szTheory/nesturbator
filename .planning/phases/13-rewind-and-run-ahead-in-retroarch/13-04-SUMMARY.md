# Phase 13 Plan 04: State-loader fuzz target and committed corpus Summary

A fuzz target for `nesturbator_load_state` runs twelve synthetic carts through harness-side oracles, with a 17-seed corpus generated by the harness itself, drift-checked by `fuzz.state` and replayed by `fuzz.state.regress` in ci and asan.

## Commits

- 97c2123: tracer. `replay_file` and `main` move to `replay_main.h`; one-cart harness; `fuzz.state.seeds` fixture plus `fuzz.state.regress` (fuzz.regress unchanged and passing).
- 3b6ea8b: twelve carts, full oracle set, `--check-seeds`, 17 committed seeds with manifest lines in the same commit, final CTests, `fuzz.state.libfuzzer`, registration check, README paragraph.

## What was built

- Carts 0..11: boards 0, 1, 2, 3, 4, 7, each small and maximum (m2-max is 255 x 16 KiB PRG, m4-max 512 KiB PRG and 256 KiB CHR, m1-max 512 KiB PRG with CHR RAM). Image = iNES 1 header plus an integer LCG fill, cached per cart.
- Oracles (all `abort()`): refused load leaves `save_state` bytes identical and returns a documented status; accepted load must be exact length, `save(load(S))` equals S with bytes 16-19 set to the behaviour revision and the CRC recomputed, a second fresh instance loading S accepts it and gives equal video/audio/status/frame/tick hashes over 2 frames, the saved state reloads into a fresh instance, save-load-save is stable.
- No change to `src/` (`git diff --stat main -- src` empty); the CRC-32 is a copy in the harness.
- `fuzz.state_loader --check-seeds` fails when a committed seed differs, a generated seed is missing, an extra file lacks the `regress-` prefix, or a `valid-*` seed is not accepted. An empty corpus glob fails configuration (shown directly while bootstrapping).
- Largest state size seen among the 12 carts: 45,869 bytes (m1-max). Others: 4,895 to 4,896 (m0, m3, m2-max), 13,088 (m2-small, m7), 13,101 (m1-small), 13,111 (m4), as measured by `nesturbator_state_size`.
