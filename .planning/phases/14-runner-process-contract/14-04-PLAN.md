Case `term_exitflush` (research Pitfall 3): no `--save-interval`. Readiness is not a stdout line, because stdout to a pipe is fully buffered by C stdio and a hash line would not arrive until exit; instead spawn `RUNNER --rom FIXTURE_DIR/battery.nes --frames 4294967295 --save-dir WORK_DIR --state-at-frame 1:WORK_DIR/ready.state` and wait until ready.state exists with non-zero size (it is written by temp and rename after frame 1, so its presence means frame 1 ran and the handler is installed). CHECK battery.sav does not exist at that point (only the exit flush may write it). Then SIGTERM, timed as in `term`; CHECK exit 0, `ms <= 2000`, battery.sav 8192 bytes starting `SAVE`, no battery.sav.tmp. Print `signal-to-exit <ms> ms`.

Case `second` (D-15): copy FIXTURE_DIR/seed.sav to WORK_DIR/battery.sav (read and write in C). Create a pipe; spawn `RUNNER --movie FIXTURE_DIR/stall.nmovie --rom FIXTURE_DIR/battery.nes --save-dir WORK_DIR` with stdout on the pipe's write end, close the write end in the parent, and never read or close the read end until the child is reaped (closing it would turn the stall into SIGPIPE). Stalled means `ioctl(read_fd, FIONREAD, &n)` gives `n > 0` and the same value on three polls 50 ms apart, within the readiness deadline. Send SIGTERM once; then poll `waitpid(WNOHANG)` for 500 ms and CHECK the child is still alive (restart semantics: the blocked write resumes). Then send SIGTERM every 100 ms until the child is reaped or 5000 ms pass (research Pitfall 6: repeats are harmless because the disposition is now default). CHECK `WIFSIGNALED` and `WTERMSIG == SIGTERM`; CHECK battery.sav is byte-equal to seed.sav and no battery.sav.tmp exists.
