<assumption_delta_decision>
Detector signal: pluralization on "a second signal ends the runner at once".
Primary noun: the stop request, one flag per runner process.
Decision: no-change. "Second" means a repeated delivery of a signal to the same process, not a second identity, platform or source of truth. One flag and one handler per platform stay the model; the second delivery is handled by the default action (POSIX `SIG_DFL` reset, Windows handler returning FALSE), not by a second state.
Invariant test (accepted, already in scope): runner.stop.double (Plan 03) and runner.signal.second (Plan 05) fail if a later signal is ever treated as another graceful stop.
</assumption_delta_decision>

Case one, the launcher shares the runner's console: it starts the runner with `CREATE_NEW_PROCESS_GROUP` (and without `CREATE_NEW_CONSOLE`, `DETACHED_PROCESS` or `CREATE_NO_WINDOW`) and stops it with `GenerateConsoleCtrlEvent(CTRL_BREAK_EVENT, pid)`, the runner's process id being its group id, so only the runner's group gets the event.
