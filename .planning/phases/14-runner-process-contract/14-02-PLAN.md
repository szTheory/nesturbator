<assumption_delta_decision>
Detector signal: pluralization on "a second signal ends the runner at once".
Primary noun: the stop request, one flag per runner process.
Decision: no-change. "Second" means a repeated delivery of a signal to the same process, not a second identity, platform or source of truth. One flag and one handler per platform stay the model; the second delivery is handled by the default action (POSIX `SIG_DFL` reset, Windows handler returning FALSE), not by a second state.
Invariant test (accepted, already in scope): runner.stop.double (Plan 04) and runner.signal.second (Plan 06) fail if a later signal is ever treated as another graceful stop.
</assumption_delta_decision>

Create `runner/stop.h` (guard `NESTURBATOR_RUNNER_STOP_H`) declaring the six functions and three kind macros listed in the artifacts table. Its header comment says: runner-only, the core library links only the C memory functions; the handler only records the request; the loop checks it before each frame; what each platform handles (per D-24) with citations to POSIX/C17 `signal` and the Microsoft Learn `HandlerRoutine` and `SetConsoleCtrlHandler` pages.

Create `runner/stop.c` with `#define _DEFAULT_SOURCE` as the very first line. Its comment says two things: glibc gives `signal()` BSD (SA_RESTART) semantics only with this macro (research Pitfall 1, signal(2)); and `_DEFAULT_SOURCE` is a feature-test macro that only makes POSIX and BSD declarations visible in the system headers, so the compiler mode stays `-std=c17` without extensions (CLAUDE.md language constraint). POSIX half (`#ifndef _WIN32`), per D-02: `static volatile sig_atomic_t stop_flag;` a static handler `on_signal(int sig)` that calls `(void)signal(sig, SIG_DFL);` then stores 1; install does `(void)signal(SIGINT, on_signal); (void)signal(SIGTERM, on_signal);`; `stop_done` is empty; parse_kind accepts `int` and `term`; default is TERM; raise calls `raise(SIGINT or SIGTERM)` count times. Windows half (`#ifdef _WIN32`, `WIN32_LEAN_AND_MEAN`, `<windows.h>`), per D-03: `static volatile LONG` for the requested flag, the done flag and the C/BREAK event count, plus `static DWORD` close cap (default 4500) and grace (default 1000); `nesturbator_run_stop_handler(DWORD type)`: CTRL_C_EVENT and CTRL_BREAK_EVENT set the flag with `InterlockedExchange` and return TRUE for the first event and FALSE for any later one (`InterlockedIncrement` on the count); CTRL_CLOSE_EVENT sets the flag, then loops `Sleep(10)` until the done flag (read with `InterlockedCompareExchange(&v, 0, 0)`) or the cap elapses (`GetTickCount64`, unsigned arithmetic), then, if done was seen, keeps waiting a fixed grace measured from the instant it observed the done flag (record `GetTickCount64()` at that instant and loop `Sleep(10)` until the grace interval has elapsed, even though done is already set; the whole wait stays bounded by the cap measured from the start of the CLOSE event), and returns TRUE; every other event returns FALSE. Install calls `SetConsoleCtrlHandler(nesturbator_run_stop_handler, TRUE)` and ignores the result. `stop_done` sets the done flag. parse_kind accepts `int` and `break`; default is BREAK. raise calls the handler with CTRL_C_EVENT or CTRL_BREAK_EVENT count times and, when it returns FALSE, calls `ExitProcess(0xC000013Au)` (a local constant `STOP_CONTROL_C_EXIT` with a comment that it is the status the default handler leaves, STATUS_CONTROL_C_EXIT). No CRT `signal`/`raise` on Windows and no call to the console attach, allocate or free functions; a comment that names them writes the bare name without an opening parenthesis after it. Avoid MSVC C4127 (no constant conditions), C4100 and narrowing warnings (Pitfall 11).
