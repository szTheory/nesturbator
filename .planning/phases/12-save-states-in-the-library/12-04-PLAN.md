## Decisions taken under Claude's discretion

- **Test split (discretion):** one executable, `core.state_fork`, takes the ROM paths as arguments and a `--short` flag; the six-board list lives in `tests/CMakeLists.txt` next to the registration. The driver reads each ROM file into memory and hands the bytes to `fork_image`, so Plan 05's synthetic image takes the same path.
- **Digests, not stored frames:** the uninterrupted run records per-frame CRC-32 of the video and of the audio samples (via `nesturbator__crc32`), ticks and frame_number, so memory stays small; the final state bytes are compared exactly.
- **asan fork set (RESEARCH P20, fixed at planning):** `--short` uses `{0, 1, 30}` over E = 60 and a 10-frame other-game pre-fill. Each fork costs pre-fill + (K + 7) + (E - K) = 77 frames whatever K is, so the set is sized by fork count, not by which frames: three forks keep frame 0 (power-on), frame 1 (first boundary) and one mid-run point. The fixed fallback if the asan run is over 120 s is to skip the save-every-frame run under `--short`.
- **"Another game" pre-fill (RESEARCH P13):** loading a different cartridge resets almost every field, so the pre-fill is layered: another game for 30 frames (10 under `--short`), then the same ROM on different input, then the 0xA5 poison. The poison keeps `mapper.id`, `mapper.submapper`, `cart` pointers and sizes, the `map` page tables and ops, and `allocator` intact so the identity check passes and APPLY can rebuild.
- **Assumption delta:** "another game" is a test pre-fill, not a second identity model; decision `no-change` (see 12-01).
