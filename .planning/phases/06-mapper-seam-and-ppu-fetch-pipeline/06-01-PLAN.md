## Decisions taken under Claude's discretion

- **D-01 implementation constraint (orchestrator direction 1):** the ops struct is held by value in `nes->map.ops` and filled by `nesturbator__mapper_nrom_ops`, called from the resolver `nesturbator__mapper_load` in `cartridge.c` (D-01: "chosen at load"). A `static const` struct of function pointers is `.data.rel.ro` under `-fPIC` and `nm` types it `d`, which fails `abi.global_symbols` in the Linux `nofp` job. D-01's members, the `watch`-guard rule and "no switch in bus.c or ppu.c" are unchanged. Not a revision conflict.
- **`last A12 level`** (D-02) is the field `uint8_t a12` in `struct nesturbator__map`; it is declared here and first written by Plan 02's bus driver.
- **`$4018-$401F`** stays outside the page lookup: reads keep open bus, writes drop, exactly as now. The lookup covers `$4020-$FFFF`.
- **Zeroed instance mirroring:** a zeroed `map.nt` is `{0,0,0,0}` (single-screen A) where v1 used horizontal with no cartridge. Only zeroed-instance unit tests can see it; `frame.c` never runs the PPU without a cartridge (src/frame.c:41), so no hash can move. The mirroring test moves to the fixture.
- **File budget (checker revision):** the plan stays under 15 files by three moves that keep every locked decision. (1) No `src/mapper.c`: the resolver lives in the loader (`cartridge.c`), where D-01 says the board is chosen, and the two page helpers are `static inline` in `internal.h` (the ladder's "reuse what is here"; no new symbol for `abi.global_symbols` either). (2) The header-to-`nt[]` check and the soft-reset-keeps-the-board check live in `core.mapper` instead of `ppu.registers` and `core.reset`, so `tests/core/test_reset.c` is untouched. (3) The three PPU unit tests point `map.chr_r[]`/`map.nt[]` of their zeroed instance at their own arrays instead of loading a fixture; the fixture header moves to Plan 02, whose `ppu.fetch` first needs a loaded NROM.
- **README (CLAUDE.md rule 6):** this plan changes no behaviour a user can observe (every frame and audio hash, the public header and the revision stay as they are), so README is not touched here. The sentence that cartridges load through a per-board mapper interface lands in Plan 02 Task 1, together with the first behaviour that interface carries (A12 to the board).
- **Commit shape:** Task 1's commit leaves `ppu.render`, `ppu.sprites` and `ppu.registers` red because they set the retired cartridge fields by hand; Task 2 migrates them first. The branch is squash-merged (as every PR on `main`), Task 1's commit is never pushed alone, and the pushed seam commit (Task 2's) passes the full `ci` workflow.
