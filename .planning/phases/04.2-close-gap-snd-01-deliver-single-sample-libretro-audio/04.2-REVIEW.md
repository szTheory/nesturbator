## Summary

Reviewed the adapter's audio dispatch, public documentation, and host coverage. Batch-first dispatch and ordered sample fallback are consistent with the documented mono-to-stereo contract. The host test does not substantiate the documented failed-frame no-audio behavior.

## Warnings

### WR-01: Failed-frame callback behavior is untested

**File:** `tests/libretro/libretro_host.c:364-468`
**Issue:** `check_sound_frame_parity` only runs successful audible frames, and the no-content check also runs a successful frame. It never registers audio callbacks and forces `nesturbator_run_frame` to fail through the adapter (for example, by loading a fixture that executes JAM). As a result, the asserted behavior in `libretro.c` that a failed frame sends no audio has no host-level regression coverage; a future change could dispatch stale or partially produced audio on this return path without this test detecting it.
**Fix:** Add a libretro host case that registers callbacks, runs a cartridge which causes `nesturbator_run_frame` to return a failure status, then asserts that neither the batch nor sample callback was called for that run.
